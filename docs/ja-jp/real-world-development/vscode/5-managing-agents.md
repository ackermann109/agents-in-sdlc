agent mode の GitHub Copilot は、コードベースを調べ、変更を提案してファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、その作業をリアルタイムで確認できます。差分をインラインでレビューし、変更ごとに採用または取り消しを選び、追加のプロンプトでエージェントに指示を出せます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッションの途中でエージェントに指示し、高コントラストに加えてライトモードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、高コントラスト モードを実装中です。作業の途中で、デザインチームから新たにライトモードの切り替えも追加してほしいと依頼されました。会話を最初からやり直すのではなく、既存のセッションに指示を追加します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集などが表示されます。各ファイル編集は差分と **Keep** / **Undo** の操作とともに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツールの実行を確認します。ファイルの読み取りと編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントが編集を提案したら、差分を確認します。
   - 変更を採用するには **Keep** を選択します。
   - 変更を取り消してエージェントに再度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開き、このセッション中にエージェントが変更したファイル全体を確認することもできます。

> [!NOTE]
> ターミナル コマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけ承認してください。

5. エージェントが高コントラスト モードの実装を終えるまで待ちます。完了すると、変更内容をまとめた最終メッセージが表示されます。

## エージェントにライトモードを追加するよう指示する

高コントラスト モードができたら、同じ会話でライトモードの切り替えを追加します。会話を続けることで、エージェントは前の作業で変更したコンポーネントやスタイル、ローカルストレージの使い方を引き継ぎます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントが以前の変更を確認し、ライトモードの追加を提案する様子を確認します。
3. 追加された各編集をレビューし、**Keep** または **Undo** を選択します。
4. トグル UI を不要にリファクタリングするなど、望ましくない方向に進んだ場合は、チャット入力欄の横にある **Stop** ボタンで停止し、追加の説明を送ります。

> [!TIP]
> 実行中のセッションに追加のプロンプトを送ると、最初からやり直すより早く修正できます。「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」、「3 つ目のトグルを作らず、既存の設定パネルにライトモードを追加する」、「両方のトグルにキーボード ショートカットも追加する」などと指示できます。

## 作業内容をレビューする

コミットする前に、エージェントが変更したファイル全体を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルをすべて確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントが指定した ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定の保存が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat agent mode で、進行中のセッションを監視して方向付けしました。各ファイルの編集をレビューし、採用または取り消しを選び、会話のコンテキストを保ったまま追加のプロンプトで作業を広げました。

この演習では、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または取り消しました。
- 追加プロンプトでセッションの途中からエージェントに指示しました。

次の[レッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、このラボでローカルのカスタム エージェントが行った変更をレビューします。
